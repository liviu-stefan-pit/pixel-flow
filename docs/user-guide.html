What PixelFlow can do

PixelFlow is a Windows attended RPA studio: you author a human-readable automation project, then a separate Runner process drives real UI elements on your unlocked desktop. It is built for reliability under UI drift — timing variance, DPI changes, window movement — and is designed to fail loudly rather than click the wrong thing.

In scope for v1
  • Click, Type, and Wait steps against desktop apps
  • Ordered locator chains: UIA → Win32 → OCR → Image
  • Bounded retries, recovery (skip / jump / abort)
  • Secrets by reference (Credential Manager)
  • Run reports (JSONL) and opt-in failure screenshots
  • Pause / resume, emergency stop, interference pause
Not magic — know the edges
  • UAC / secure desktop / lock screen are not automatable
  • Elevated (admin) windows are blocked by UIPI in v1
  • No unattended / scheduled / locked-session runs
  • No embedded C# / Python / JS in projects
  • Step types today: Wait, Click, Type only

Target technologies that work well: WPF, WinForms, Win32/MFC, UWP/WinUI (including modern Calculator), Chromium/Electron where accessibility is exposed. Custom-drawn canvases fall back to OCR or image matching.

Studio and Runner

PixelFlow deliberately splits into two OS processes so a hung target app cannot freeze the editor, and so a project never runs with the editor’s full file/credential surface.

ProcessOwnsDoes not own
Studio Project files, list editor, snipping, UIA inspector, test-locator, trust prompt, report summary, Run/Pause/Stop IPC SendInput, live locator resolution during a run, Credential Manager secret values
Runner Locator chain, retries, verified input, clipboard restore, emergency hotkey, JSONL reports, secret resolve Project editing UI
Rule of thumb
Author and validate locators in Studio. Let Runner be the only process that touches the target UI during a run. If something feels flaky, fix the locator chain — do not lengthen waits forever.

Project model

A project is a folder ending in .pflow. The canonical truth is project.json — not the visual editor state. 

my-flow.pflow/
  project.json          # schema, steps, locators, retries
  assets/               # sha256-<hash>.png snips
  history/              # rolling backups on save
  reports/run-…/        # events.jsonl (+ optional PNGs)

Step types

typePurposeKey fields
Wait Pause between actions (also a natural pause/resume boundary) waitMs
Click Resolve a target, re-check, then click locator
Type Focus a field and paste text (clipboard snapshot/restore) locator, text or secretRef

Defaults that keep runs bounded

  • defaults.timeoutMs — per-attempt resolve poll budget (default 5000)
  • defaults.retry.maxAttempts / backoffMs — finite retry budget
  • defaults.captureFailureScreenshots — off by default (privacy)
  • Per-step recovery: Skip, Jump (to step id), or Abort

Locator techniques (all layers)

Every Click/Type step resolves through an ordered chain scoped to a process (and optional window title). The Runner stops at the first enabled layer whose confidence meets its threshold, and records the winning layer in the report.

#kindWhen to usePrimary fields
1 UiaStructural Best default. Stable AutomationId + ControlType + Name automationId, controlType, name
2 UiaSemantic Apps that expose Name/ControlType but omit AutomationId name, controlType (no AutomationId)
3 Win32 Legacy controls with weak UIA (class + control ID) windowClass, controlId
4 Ocr Visible text with no useful accessibility tree text (fuzzy-matched)
5 Image Icons / custom-drawn UI — last resort imageAssetHash (from Snip)
Authoring discipline
Prefer UIA. Keep OCR/Image as fallbacks in the same chain, not as your first layer, unless the control truly has no accessibility. Always set locator.scope.processName so you never match the wrong app instance.

How to use it properly

  1. Install or build. Packaged install: .\scripts\pack.ps1 then .\scripts\install.ps1 (needs .NET 10 Desktop Runtime). Or run Studio from source with dotnet run --project src/PixelFlow.Studio.
  2. Open the target app on an unlocked interactive desktop (Calculator, Notepad, your app). PixelFlow will not fight a lock screen or UAC prompt.
  3. Create a project. In Studio: New → Save into a something.pflow folder. Accept the trust prompt when asked — untrusted projects can be edited but cannot Run.
  4. Inspect before you guess. Enable UIA Inspector, hover the control, copy AutomationId / Name / ControlType / process name into the step. Use Test locator to highlight the live match without running the whole script.
  5. Author the shortest reliable chain. Start with one UIA layer. Add Win32 / OCR / Image only when higher layers fail on purpose. Snip images into assets/ when you need the Image layer.
  6. Bound time. Keep timeoutMs and retry.maxAttempts finite. Prefer recovery steps over “retry forever.”
  7. Run with an escape hatch. Memorize Ctrl+Shift+F12 (global emergency abort). If you wiggle the mouse mid-action, Runner may pause for interference — Resume when ready.
  8. Read the report. Open Last report or reports/run-*/events.jsonl. Check which layer= won and why a step failed.

Type steps and secrets

Type focuses the locator target and pastes via the clipboard, then always restores the previous clipboard contents. For credentials, set secretRef to a Windows Credential Manager Generic target name (for example PixelFlow/MyLogin). The secret value never appears in project.json or run reports.

Safety model and limitations

  • Projects are executable content. Trust is remembered under %LocalAppData%\PixelFlow\trusted-projects.json.
  • No arbitrary code execution inside a project file.
  • Emergency stop and user-interference pause exist so automation yields to the human.
  • Click post-check in the current live Runner path is tightly coupled to the PixelFlow Test Bench click counter. When automating Calculator/Notepad, treat “resolved + clicked without wrong-target guesses” as success, and assert outcomes yourself (display text, file contents) until general post-conditions land.
Do not expect these to work
Automating through UAC consent, the login/lock screen, DRM-protected surfaces, or elevated admin windows from a standard-integrity PixelFlow process.

Example 1 — Calculator: 7 + 5 = 12

Primary technique: UIA structural locators on Windows Calculator (WinUI / UWP).

UiaStructural Click Wait Windows Calculator

Goal

Launch Calculator yourself, then run a PixelFlow project that clicks 7, +, 5, =. Modern Calculator exposes stable AutomationIds such as num7Button, plusButton, num5Button, equalButton.

Authoring steps in Studio

  1. Start Calculator (Start → Calculator).
  2. Studio → New → Save as calc-add.pflow. Trust the folder.
  3. Enable UIA Inspector; hover 7. Confirm AutomationId num7Button, ControlType Button, process roughly CalculatorApp (Windows 10/11 may show ApplicationFrameHost for the frame — use the process name the inspector reports).
  4. Add four Click steps (optionally short Waits between them).
  5. Use Test locator on each button before Run.

Complete project.json

{
  "schemaVersion": 1,
  "name": "calc-add",
  "variables": {},
  "defaults": {
    "timeoutMs": 5000,
    "retry": { "maxAttempts": 3, "backoffMs": 250 },
    "captureFailureScreenshots": false
  },
  "steps": [
    {
      "id": "press-7",
      "type": "Click",
      "timeoutMs": 5000,
      "retry": { "maxAttempts": 3, "backoffMs": 250 },
      "locator": {
        "scope": {
          "processName": "CalculatorApp",
          "windowTitle": "Calculator"
        },
        "layers": [{
          "kind": "UiaStructural",
          "enabled": true,
          "confidenceThreshold": 0.9,
          "automationId": "num7Button",
          "controlType": "Button",
          "name": "Seven"
        }]
      }
    },
    {
      "id": "press-plus",
      "type": "Click",
      "timeoutMs": 5000,
      "retry": { "maxAttempts": 3, "backoffMs": 250 },
      "locator": {
        "scope": { "processName": "CalculatorApp", "windowTitle": "Calculator" },
        "layers": [{
          "kind": "UiaStructural",
          "enabled": true,
          "confidenceThreshold": 0.9,
          "automationId": "plusButton",
          "controlType": "Button",
          "name": "Plus"
        }]
      }
    },
    {
      "id": "press-5",

      "timeoutMs": 5000,

        }]

Localization & process name
Button name strings follow the OS language (“Seven” vs localized text). Prefer AutomationId when present. Always copy processName from the Studio inspector on your machine — do not hard-code from memory if Test locator fails.

Run

dotnet run --project src/PixelFlow.Runner -- --run-project path\to\calc-add.pflow
# or open the folder in Studio and click Run

Expected: Calculator display shows 12. Report events should show layer=UiaStructural for each click.

Example 2 — Notepad: type a note, then click File

Techniques: UIA structural + UIA semantic, Type with clipboard restore, Wait, optional secretRef.

UiaStructural UiaSemantic Type Wait Notepad

Goal

Automate classic or modern Notepad: focus the editor, type a sentence, wait, then click the File menu via a semantic name match (menus often lack a convenient AutomationId). Demonstrates Type’s clipboard restore and a two-layer locator style.

Authoring steps

  1. Open Notepad.
  2. Inspector → hover the large edit surface. Note AutomationId (often 15 on classic Win32 Notepad, or a WinUI id on modern Notepad) and ControlType Edit / Document.
  3. Add a Type step with plaintext, or set secretRef if the payload is sensitive.
  4. Add a short Wait.
  5. Add a Click on File using UiaSemantic (name: "File", controlType: "MenuItem") with an optional structural layer first if an AutomationId exists.

Complete project.json

{
  "schemaVersion": 1,
  "name": "notepad-type-file",
  "variables": {},
  "defaults": {
    "timeoutMs": 6000,
    "retry": { "maxAttempts": 3, "backoffMs": 300 }
  },
  "steps": [
    {
      "id": "type-body",
      "type": "Type",
      "timeoutMs": 6000,
      "retry": { "maxAttempts": 3, "backoffMs": 300 },
      "text": "PixelFlow typed this note at attended desktop time.",
      "locator": {
        "scope": {
          "processName": "Notepad",
          "windowTitle": "Untitled - Notepad"
        },
        "layers": [
          {
            "kind": "UiaStructural",
            "enabled": true,
            "confidenceThreshold": 0.9,
            "automationId": "15",
            "controlType": "Edit",
            "name": "Text Editor"
          },
          {
            "kind": "UiaSemantic",
            "enabled": true,
            "confidenceThreshold": 0.85,
            "controlType": "Edit",
            "name": "Text Editor"
          }
        ]
      }
    },
    {
      "id": "pause",
      "type": "Wait",
      "waitMs": 400
    },
    {
      "id": "click-file",
      "type": "Click",
      "timeoutMs": 6000,
      "retry": { "maxAttempts": 3, "backoffMs": 300 },
      "locator": {
        "scope": {
          "processName": "Notepad",
          "windowTitle": "Untitled - Notepad"
        },
        "layers": [
          {
            "kind": "UiaSemantic",
            "enabled": true,
            "confidenceThreshold": 0.85,
            "controlType": "MenuItem",
            "name": "File"
          }
        ]
      }
    }
  ]
}
Clipboard & secrets
Copy something known (for example CLIP-BEFORE) before Run. After the Type step finishes, your clipboard should still be CLIP-BEFORE — PixelFlow restores it even if the paste path fails mid-step. For sensitive payloads, replace text with "secretRef": "PixelFlow/DemoNote" (Generic credential in Credential Manager) and omit plaintext from the JSON.

Modern Notepad note

Windows 11 Notepad may run as Notepad with different AutomationIds and a title like Untitled — Notepad. Always verify with Inspector + Test locator. If UIA is thin on a control, keep the semantic layer enabled as shown.

Example 3 — Resilient Calculator equals with every fallback

One Click step that teaches the full chain: UIA → Win32 → OCR → Image, plus recovery.

UiaStructural Win32 Ocr Image Recovery Calculator

Goal

Click Calculator’s Equals control using a full locator chain. On a healthy Windows 11 Calculator, layer 1 (UIA) wins. The remaining layers are present so you can break higher layers during practice and watch the report fall through — the same pattern you will need for legacy or custom-drawn UI.

Prepare assets

  1. Open Calculator; Studio open on calc-equals-chain.pflow.
  2. Select a Click step → Snip a tight rectangle around the = key only. Studio stores assets/sha256-….png and can attach an Image layer automatically.
  3. Copy the hash into the Image layer below (or keep the Studio-authored token).
  4. Optional Win32 layer: only useful if Inspector / Spy++ shows a real BUTTON + control id. Modern Calculator usually will not — leave it disabled or omit it; it is shown here for completeness on Win32-friendly apps.

Complete project.json

{
  "schemaVersion": 1,
  "name": "calc-equals-chain",
  "variables": {},
  "defaults": {
    "timeoutMs": 8000,
    "retry": { "maxAttempts": 3, "backoffMs": 300 },
    "captureFailureScreenshots": true
  },
  "steps": [
    {
      "id": "warmup-wait",
      "type": "Wait",
      "waitMs": 500
    },
    {
      "id": "click-equals",
      "type": "Click",
      "timeoutMs": 8000,
      "retry": { "maxAttempts": 3, "backoffMs": 300 },
      "captureFailureScreenshot": true,
      "recovery": {
        "action": "Abort"
      },
      "locator": {
        "scope": {
          "processName": "CalculatorApp",
          "windowTitle": "Calculator"
        },
        "layers": [
          {
            "kind": "UiaStructural",
            "enabled": true,
            "confidenceThreshold": 0.9,
            "automationId": "equalButton",
            "controlType": "Button",
            "name": "Equals"
          },
          {
            "kind": "UiaSemantic",
            "enabled": true,
            "confidenceThreshold": 0.85,
            "controlType": "Button",
            "name": "Equals"
          },
          {
            "kind": "Win32",
            "enabled": false,
            "confidenceThreshold": 0.9,
            "windowClass": "BUTTON",
            "controlId": 1
          },
          {
            "kind": "Ocr",
            "enabled": true,
            "confidenceThreshold": 0.7,
            "text": "="
          },
          {
            "kind": "Image",
            "enabled": true,
            "confidenceThreshold": 0.8,
            "imageAssetHash": "sha256-REPLACE_WITH_YOUR_SNIP_HASH"
          }
        ]
      }
    },
    {
      "id": "after-success",
      "type": "Wait",
      "waitMs": 200
    }
  ]
}
Win32 layer on Calculator
Leave Win32 enabled: false for modern Calculator (no classic BUTTON control ids). Enable it when practicing against Win32 apps — PixelFlow Test Bench’s native button uses windowClass: "BUTTON" and controlId: 1001 (see fixture win32-click.pflow).

Practice drills (learn every technique)

DrillWhat to changeWhat the report should show
Happy path Leave UIA enabled layer=UiaStructural
Semantic only Set UiaStructural enabled: false layer=UiaSemantic
OCR fallback Disable both UIA layers; keep OCR text = or Equals layer=Ocr with confidence ≥ 0.7
Image fallback Disable UIA + OCR; keep Image snip layer=Image
Win32 path Retarget scope to a Win32 app (e.g. PixelFlow Test Bench native button: class BUTTON, id 1001) and enable the Win32 layer layer=Win32
Hard fail + screenshot Wrong AutomationId, all layers disabled or mismatched FailedStep, optional failure-click-equals.png, recovery Abort
Recovery variants
Change recovery.action to Skip to continue to after-success after failure, or Jump with "jumpTo": "after-success". Omitting recovery still aborts.

Diagnosing runs

  • events.jsonl — step id, timestamps, resolve attempts, winning layer, confidence, outcome.
  • layer= in Runner logs — if you expected UIA but see Image, the app’s accessibility tree probably drifted; fix UIA before shipping.
  • Exit codes (--run-project): 0 success (Idle), 3 failed/aborted; --resolve uses 2 for not found.
  • Interference — status Paused with an interference message; Resume continues with a fresh resolve.
  • Display / DPI changes — Runner invalidates cached absolute coordinates and re-resolves; do not rely on frozen pixel positions.
